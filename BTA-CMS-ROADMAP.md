# BTA CMS Roadmap — Execution Checklist

**This is the active, cross-session execution checklist for finishing the British Trade Awards CMS as a commercial-grade platform.** It is referenced from `CLAUDE.md` and `BTA-CMS-PROJECT-TASKS.md` as the standing source of truth for *what's next*; those two files remain the authoritative record of *what already happened* (decisions, evidence, git/recovery history). Check items off (`[x]`) and update the Status Log in the same commit as the work that completes them.

**A note on evidence, carried over from this project's standing continuity protocol:** items below that are genuinely new, unscoped feature work (most of Phase 1–3) are written as outcomes and known starting points, not as a settled technical spec — several explicitly say "target files/approach: TBD, needs investigation" rather than guessing at a design before anyone has looked at the relevant code. Treat those lines as honest gaps to fill in during that item's own session, not as oversights.

**Prior work, not re-logged here:** substantial related work already merged into `main` before this roadmap existed — the nominee-upload pipeline audit, London-borough public/admin sync, the bulk-upload Award Year selector, the `winners.access_token` public-API leak fix, migrations 093/095/096, and the 4-way `feature/safe-reconciliation` split (PRs #361–#365). Full history for that work is in `BTA-CMS-PROJECT-TASKS.md` Sections II–III, not duplicated here.

### `[x]` 1.3 — Season Rollover Wizard
**Status: Done. Branch `claude/season-rollover-wizard`. Full evidence in `BTA-CMS-PROJECT-TASKS.md` Section IX.**
- Goal: one-click clone of a season's award categories into a new award year, without duplicating prior years' nominees.
- What was actually found (none of this was assumed): **three separate, pre-existing, already-wired "clone awards to next year" code paths already existed** in `awards.js` before this task — `rolloverToNextYear()` (auto-detects source as the most recent loaded year, target = source+1; a "Roll Over to Next Year" dropdown item), `cloneAward()`/`confirmCloneAward()` (single-award clone via a small modal with a free year input), and `bulkCloneSelected()` (bulk-selected clone via a browser `prompt()` for the year). Left all three untouched (zero regression risk to their own existing, passing tests) and built the wizard as new, separate, dedicated code — flagged as a real DRY/consolidation opportunity for its own future task, not fixed unilaterally here.
- Also found: a third, unrelated "season" concept — `award_seasons` (a Settings-managed table of named date templates, bulk-applied onto selected awards via `bulkApplySeasonDates()`) — confirmed distinct from `award_years.year` (the integer used by the 1.1 Global Season Switcher, Award Areas, and this wizard) and left untouched.
- No flat "standard categories" master list exists in the schema (same finding as 1.2) — "clone standard award categories" was built as "clone every `award_years` row that exists for the chosen Source Season" (which is already per-area, per the established architecture), skipping any that already exist in the Target Season by the same `award_name + area_id/county` duplicate key `rolloverToNextYear()` already used.
- Target files: `awards.js` (`openRolloverWizard`, `updateRolloverPreview`, `confirmRolloverWizard`), `season-switcher.js` (new `refresh()` method), `src/partials/00-shell-head.html` ("Start New Season" navbar button), `src/partials/99-shell-foot.html` (wizard modal), `tests/awards.test.js`, `tests/season-switcher.test.js`.
